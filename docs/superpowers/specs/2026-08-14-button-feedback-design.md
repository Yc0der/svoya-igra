# Заметный отклик на клик — дизайн

Идея из `docs/ideas.md` («Настоящий эффект нажатия кнопки»), одобрена в брейнсторминге
2026-08-14. Чистая CSS-полировка — ни один компонент, ни одна логика не меняются.

## Правило

Причина, зафиксированная в самой идее: живая проверка 2026-08-06 показала, что ведущий,
нажимая «Зачёт»/«Незачёт» на телефоне, не может понять, сработал клик или нет — на телефоне
нет наведения мыши, а браузерная обратная связь по умолчанию слабая, и видимое изменение
(рамка `.is-selected`) появляется только после того, как React перерисует компонент по
результату клика — то есть с задержкой, зависящей от того, как быстро сработал обработчик.

Решение — два независимых слоя, оба чистый CSS:

1. **`:active` у каждой кнопки в игре** (`.button`, общий класс — используется вообще
   везде: обычная кнопка выбора вопроса, buzz, голосование/судейство, ставки в аукционе,
   «Пас», выбор темы в финале, панель ведущего). Срабатывает браузером мгновенно на
   `touchstart`/`mousedown`, **до** того, как вообще отработает обработчик клика и тем более
   до того, как придёт ответ сервера — тактильная реакция не зависит от сети.
2. **Более заметный `.is-selected`** — состояние «уже выбрано» (проголосовал, выбран
   LAN-адрес в `/admin`, выбран пакет). Сейчас это одна и та же рамка `outline: 4px solid`,
   продублированная **байт-в-байт** в трёх местах CSS (голосование, выбор адреса, выбор
   пакета) — усиливается один раз, для всех трёх сразу.

Вибрация (`navigator.vibrate`) в этот заход не входит — по решению при брейнсторминге,
project doctrine (`.claude/skills/svoya-igra-dev/SKILL.md`, «Ловушки», «Возможности браузера
без HTTPS») явно требует сначала проверить её на живом телефоне: игра работает по `http://`
на локальном адресе, а вибрация в большинстве браузеров требует «защищённого контекста»
(HTTPS) — без проверки заранее не узнать, сработает ли она вообще. Откладывается в
`docs/ideas.md` отдельной записью до живой проверки.

## Инвариант, который эта идея не трогает

Ни один `.tsx`-файл не меняется. Только `client/src/index.css`. Никакой логики — только
внешний вид уже существующих состояний (`:active` — состояние браузера, `.is-selected` —
уже существующий CSS-класс, применяемый компонентами как раньше).

## Изменения в CSS

**`client/src/index.css`, класс `.button`** (текущее определение, строки 264–273) — добавить
`transition` и новое правило `:active`:

```css
.button {
  font-size: 24px;
  font-weight: 600;
  padding: 16px 32px;
  border-radius: 12px;
  border: 2px solid var(--accent-border);
  background: var(--accent-bg);
  color: var(--accent);
  min-height: 56px;
  transition: transform 0.1s ease;
}

.button:active:not(:disabled) {
  transform: scale(0.96);
}
```

`:not(:disabled)` — обязательно: без него нажатие на задизейбленную кнопку (например,
«Ответ» во время временной блокировки после своей же неверной попытки) визуально «проседало»
бы, создавая впечатление, что клик всё-таки на что-то повлиял, хотя обработчик и не вызвался.

**Три одинаковых правила `.is-selected` объединяются в одно.** Сейчас в файле байт-в-байт
идентичное правило встречается трижды:

```css
.button--yes.is-selected,
.button--no.is-selected {
  outline: 4px solid var(--text-h);
  outline-offset: 2px;
}
```

```css
.admin-lan-candidates .button.is-selected {
  outline: 4px solid var(--text-h);
  outline-offset: 2px;
}
```

```css
.admin-packs .button.is-selected,
.player-packs .button.is-selected {
  outline: 4px solid var(--text-h);
  outline-offset: 2px;
}
```

Заменяются одним общим правилом `.button.is-selected` (класс `.button` уже присутствует на
всех перечисленных элементах — `.button--yes`/`.button--no` это модификаторы того же
`.button`, остальные явно оборачивают кнопку в `.button`), с усилением:

```css
.button.is-selected {
  outline: 4px solid var(--text-h);
  outline-offset: 2px;
  transform: scale(1.05);
}
```

Три исходных правила удаляются — поведение идентично прежнему для тех же трёх мест
(голосование, выбор LAN-адреса, выбор пакета), плюс общее визуальное усиление, без риска,
что новый код, использующий `.is-selected` на кнопке где-то ещё, забудет про рамку — раньше
пришлось бы дублировать правило в четвёртый раз, теперь работает само.

## Отказы

**Кнопка `:active` и `.is-selected` одновременно** (повторный тап по уже выбранному варианту
— например, ещё раз ткнуть в свой же голос). Оба правила используют `transform`, и они
здесь не равны по специфичности: `.button:active:not(:disabled)` — три составляющих
(класс + псевдокласс + псевдокласс внутри `:not()`), `.button.is-selected` — два (класс +
класс). Более специфичный `:active` выигрывает, независимо от порядка объявления в файле —
значит на время самого нажатия видно `scale(0.96)` (проседание), а как только палец
отпущен, класс `.is-selected` снова берёт своё и кнопка возвращается к `scale(1.05)`. Это
ожидаемое и, кажется, даже более правильное поведение, чем «выбранная кнопка не реагирует
на повторный тап вообще» — тактильный отклик на нажатие важнее в момент нажатия, чем
статус выбранности. Стоит явно проверить вживую при тестировании, не полагаясь только на
рассуждение о специфичности выше.

**`prefers-reduced-motion`.** Не учитывается в этом заходе — проект не заявлял поддержку
этой настройки нигде ещё (ни в одном другом месте CSS), заводить её только для этой фичи
было бы непоследовательным решением, выходящим за рамки задачи.
