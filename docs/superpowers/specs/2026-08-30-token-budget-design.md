Дата: 2026-08-30

## Проблема

Замер по 21 сессии проекта (`~/.claude/projects/C--Users-ib1te-Desktop-svoya-igra/*.jsonl`):

| Метрика                                             | Значение                       |
| --------------------------------------------------- | ------------------------------ |
| Сессий / запросов к модели / сообщений пользователя | 21 / 25 852\* / 1 173          |
| Прочитано контекста суммарно                        | 11,5 млрд токенов\*            |
| Средний контекст на запрос                          | 447k                           |
| Запросов модели на одно сообщение пользователя      | 22                             |
| Стартовый контекст (system + инструменты + скиллы)  | 40k (2 авг) → 93–104k (24 авг) |
| Автокомпактов за всё время                          | 60                             |

\* Счёт по записям транскрипта (`assistant`-записи), не по запросам к модели: один

им пользуется план и `/tokens`. Средний контекст на запрос и распределение по диапазонам
ниже дедуп не затрагивает — они устояли.

**87% токенов сожжено при контексте >300k, 61% — при >500k.**

Контекст перечитывается целиком на каждом вызове инструмента, а не на каждом сообщении.
Файл, прочитанный на 30-м сообщении, оплачивается ещё сотни раз до конца сессии.

Состав контекста (5 крупнейших сессий, 33,5 МБ): результаты инструментов 70%,
входы инструментов 16%, thinking 7%, текст пользователя 4%, ответы модели 2%.

Прочие наблюдения:

- Плагин `playwright` включён, вызван 0 раз; браузер использовался встроенный (2400+ вызовов).
- `context7` вызван 0 раз, но это 2 определения инструментов — оставляем.
- `github` — 353 вызова, оправдан.
- В проекте нет `CLAUDE.md`: структура выясняется заново каждую сессию.
- 24 августа сессии `4073f672` и `50ef6adc` идентичны (39 сообщений, 237M и 236M) — работа оплачена дважды.
- 5070 вызовов Bash со средним ответом 623 байта: дёшев ответ, дорог круг.

## Что НЕ делаем и почему

- **Правила на английском.** CLAUDE.md 2,3KB; разница языков ~500 токенов на запрос,
  13M из 11 500M — 0,1%. Пишем по-русски.
- **Пороги по токенам как триггер очистки.** Триггер — завершённое событие, а не число.
- **statusLine.** Не работает в десктоп-версии.
- **Скилл-«монитор», работающий параллельно.** Скилл живёт в том же контексте и сам его ест.
- **Блокирующие хуки.** Приоритет — удобство; ничего не должно мешать работе.

## Решение

### Часть 1. Базовый контекст

Выключить плагин `playwright` в `~/.claude/settings.json`. Ожидаемо снимает часть
из 85–100k стартового контекста, который оплачивается в каждом из 8 233 запросов
(25 852 записей транскрипта до дедупа по `requestId` — см. сноску в разделе «Проблема»).

### Часть 2. CLAUDE.md проекта

Новый файл в корне, ~60 строк, по-русски:

- карта проекта: `server/src`, `client/src`, `packs/`, `docs/`, `e2e/`;
- размеры горячих файлов, чтобы не читать их целиком:
  `room.ts` 1794 строки, `server.test.ts` 3894, `room.test.ts` 3789,
  `Player.tsx` 1264, `server.ts` 1073, `engine.ts` 1068, `Admin.tsx` 973;
- команды: `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`, `pnpm test:e2e`;
- правила работы с контекстом: искать по символам до чтения; читать фрагментами;
  батчить независимые команды в один вызов; разведку по коду отдавать субагентам;
- ссылки на `docs/`, без пересказа содержимого.

### Часть 3. Отчёт `/tokens`

`.claude/scripts/tokens.mjs` разбирает `.jsonl`-транскрипты и печатает ≤30 строк:
текущая сессия (размер контекста, число запросов, топ-3 пожирателя), история сессий,
оценка «сколько стоило бы при дисциплине». Вся тяжёлая работа в скрипте; в контекст
попадает только сводка. Слэш-команда `.claude/commands/tokens.md` запускает скрипт.

### Часть 4. Напоминание о точке выхода

**Инвариант безопасной очистки:** всё нужное для продолжения лежит вне контекста.
Опасность — шесть видов состояния, живущего только в контексте: невыписанное решение;
результат отладки; незакоммиченные правки; красные тесты в процессе починки;
устные поправки пользователя; план, сложившийся «в голове».

**Класс А — чистим всегда, handoff не нужен** (файл сам является передачей состояния):

- **А1.** Спека дописана и закоммичена — конец brainstorming, дальше writing-plans читает файл.
- **А2.** План дописан и закоммичен — конец writing-plans, executing-plans стартует с файла.
- **А3.** PR смёржен. Оговорка: устные правила, произнесённые в ревью, занести в CLAUDE.md до очистки.
- **А4.** Артефакт записан на диск (например, JSON-пак генератора).

**Класс Б — чистим при выполнении условия, напоминаем только когда контекст >200k**
(порог здесь не триггер, а глушитель шума):

- **Б1.** Этап плана закрыт: коммит есть, `pnpm test` и `pnpm typecheck` зелёные, прогресс отмечен в плане.
- **Б2.** Баг починен: падавший тест зелёный, фикс закоммичен, причина — в сообщении коммита.
- **Б3.** Смена темы: предыдущая задача доведена до коммита.

**Класс В — не чистим:** красные тесты или падающая сборка; незакоммиченные правки в обсуждении;
идущая отладка с неподтверждённой гипотезой; заданный и неотвеченный вопрос; середина
многофайловой правки; прочитанные, но не отработанные комментарии к PR.

**Механика.** Хук проверяет объективные факты (коммит создан, `git status` чист, тесты зелёные,
файл спеки/плана записан, PR смёржен, размер контекста из транскрипта) и дописывает пометку.
Классификацию по классу В делает модель — это понимание разговора, а не механика. Ничего не
блокируется; отказ от очистки ничего не ломает.

**Handoff для класса Б.** Секция «Состояние» дописывается в конец соответствующего файла в
`docs/superpowers/plans/`: что сделано, следующий шаг, файлы в работе, решения принятые устно.
Новых файлов не плодим, состояние едет в git вместе с фичей. Для класса А handoff не нужен.

## Размещение

- `CLAUDE.md` — корень репозитория, в git.
- `.claude/settings.json` — конфигурация хуков, в git (`settings.local.json` в gitignore).
- `.claude/scripts/tokens.mjs`, `.claude/scripts/checkpoint.mjs` — в git.
- `.claude/commands/tokens.md`, `.claude/commands/handoff.md` — в git.
- Отключение `playwright` — в `~/.claude/settings.json`, вне репозитория.

## Проверка

- `/tokens` отрабатывает и укладывается в ≤30 строк вывода.
- Хук срабатывает на коммите и не срабатывает при грязном рабочем дереве.
- Ни один хук не блокирует и не задерживает вызов инструмента.
- `pnpm test`, `pnpm typecheck`, `pnpm lint` остаются зелёными.

## Ожидаемый эффект

Части 1–2 — около 20% без изменения привычек. Часть 4 — основные ~50%.
Часть 3 сама не экономит, но показывает, работает ли остальное.
