# Удаление пакета и пропуск вопроса из админки — дизайн

Две мелкие правки интерфейса вокруг уже существующих механик, одобрены в брейнсторминге
2026-09-03. Общего между ними только то, что обе живут в `/admin` и обе делаются в один
заход; связывать их в коде нечем и не нужно.

Ни одна из двух не добавляет игре нового правила. Удаление пакета вообще не касается движка,
а пропуск вопроса — это уже реализованный `cancel-question`, которому меняется только круг
тех, кто имеет право его послать.

## Часть 1. Пропуск вопроса

### Что уже есть

`cancel-question` в `server/src/engine.ts` (`handleCancelQuestion`, около строки 639)
закрывает активный вопрос: фаза уходит в `reveal`, вопрос попадает в `answeredQuestionIds`,
очки не меняются никому. Отдельного правила писать не надо — это ровно то поведение, которое
нужно, когда за столом видно, что вопрос никто не возьмёт, и ждать оставшиеся секунды
таймера бессмысленно.

Доступна механика сейчас в одном месте: кнопка «Отменить вопрос» в панели ведущего на его
телефоне (`client/src/Player.tsx`, около строки 434). Пока ведущий не назначен, механики нет
вообще — а именно этот случай (играли вдвоём, ведущего никто не назначал) и стал поводом.

### Правило после изменения

Отменить активный вопрос может **ведущий или админ-панель**. Само поведение при отмене не
меняется ни на йоту.

В типе события `requesterId` становится `string | null`, где `null` означает «пришло с
админ-панели»:

```ts
| { type: 'cancel-question'; requesterId: string | null }
```

Проверка в `handleCancelQuestion` соответственно читается как «либо это админ-панель, либо
это назначенный ведущий»:

```ts
if (event.requesterId !== null) {
  if (state.hostId === null || event.requesterId !== state.hostId) {
    return unchanged(state);
  }
}
if (!state.currentQuestion) return unchanged(state);
return revealQuestion(state, null);
```

Отказ от посторонних игроков остаётся: игрок, приславший `cancel-question` со своим id, как
и раньше получает no-op, потому что его id не равен `hostId`. Соврать про себя `null` клиент
не может — `requesterId` подставляет сервер, а не берёт из сообщения (`server/src/room.ts`,
`cancelQuestion`, тот же принцип, что у `adjustScore` и `finalVote`).

**Почему `null`, а не второе событие.** Альтернатива — завести `admin-cancel-question` без
`requesterId`, как сделан `skip-to-final`. Это дало бы в движке вторую ветку того же правила,
дословную копию первой, и два набора тестов, которые обязаны расходиться только в одной
строке. Различие «пульт хозяина комнаты против телефона ведущего» в проекте уже существует —
здесь оно просто выражается типом, а не дублированием обработчика. Сам `skip-to-final` за
образец не берётся ещё и потому, что помечен в коде как временный.

### Транспорт

`Room.cancelQuestion` принимает `string | null` и передаёт дальше без изменений. Новое
сообщение протокола рядом с остальными админскими (`server/src/protocol.ts`):

```ts
| { type: 'admin-cancel-question' }
```

Обработчик в `server/src/server.ts` — рядом с `admin-skip-to-final`, вызывает
`room.cancelQuestion(null)`. Параметров у сообщения нет: что именно отменять, знает комната,
а не клиент.

### Интерфейс

**В `/admin`** — кнопка «Пропустить вопрос» в том же блоке, где стоит «Перейти к финалу
(тест)» (`client/src/Admin.tsx`, около строки 1206). Активна, когда `game` есть и
`game.currentQuestion !== null`; в остальных случаях выключена. От того, назначен ли ведущий,
не зависит — это и есть смысл изменения. Подтверждения нет: действие обратимо в том смысле,
что ломает максимум один вопрос, а лишний тап посреди партии дороже стоит по времени, чем по
последствиям.

**На телефоне ведущего** кнопка остаётся ровно там же, где стоит, и меняет только надпись:
«Отменить вопрос» → **«Пропустить вопрос»**. «Отменить» читается как «этого вопроса не было,
он вернётся на табло», а механика противоположная — вопрос считается сыгранным и с табло
уходит. Место кнопки не трогаем: то, что ведущий её не находил, объясняется игрой без
ведущего, а не расположением.

## Часть 2. Удаление пакета

### Что удаляется

`packs/<имя>.json` и рекурсивно папка `packs/media/<имя без .json>/`, если она существует.

Раскладка медиа не угадывается, а выводится из имени файла: URL картинки собирает
`server/src/room.ts` (около строки 1271) как
`/media/${activePackFilename.replace(/\.json$/, '')}/${image}`, и генератор пакетов кладёт
файлы туда же (`.claude/skills/pack-generator/SKILL.md`, «скачать в
`packs/media/<slug-пака>/`»). То есть у каждого пакета своя папка, названная его же именем, и
общих картинок между пакетами по построению не бывает.

Отсутствие папки медиа — не ошибка: у текстового пакета её просто нет.

### Чего сервер не удаляет

Три отказа, все на сервере, а не только в интерфейсе:

- `basename(filename) !== filename` — молча ничего не делает. Тот же охранник, что у
  `admin-update-question` и `admin-delete-question` в `server/src/server.ts`. Молча, потому
  что это не пользовательская ошибка, а попытка обхода пути: сообщать нечего.
- `*.example.json` — отказ с причиной. Это файлы репозитория, а не пакеты компании; из них
  сервер заводит рабочие копии (`ensureFileFromExample`). В списке паков их и так нет
  (`listAvailablePacks` их фильтрует), так что через интерфейс сюда не попасть — проверка
  нужна на случай прямого сообщения.
- `filename === activePackFilename` — отказ с причиной. Удалить выбранный пакет нельзя, пока
  он выбран; чтобы удалить, надо сначала выбрать другой. Так идущая партия физически не может
  остаться без картинок посреди хода, и не нужно отдельно разбирать состояние «игра идёт /
  игра не начата».

### Сервер

Новая функция в `server/src/packs.ts` рядом с `deleteQuestion`:

```ts
export async function deletePack(dir: string, filename: string): Promise<void>;
```

Удаляет json (`rm`), затем `rm(mediaDir, { recursive: true, force: true })`. Порядок именно
такой: пакет без картинок хотя бы виден и чинится, картинки без пакета — мусор, который никто
не найдёт. Несуществующий json даёт ошибку (`ENOENT` наружу как причину), а не тихий успех:
запрос на удаление того, чего нет, — рассинхрон интерфейса, о котором стоит знать.

Сообщение протокола:

```ts
| { type: 'admin-delete-pack'; filename: string }
```

Обработчик в `server/src/server.ts` — рядом с `handleDeleteQuestion`, под тем же
`withPackWriteLock`. При успехе рассылает обновлённый список:
`room.refreshAvailablePacks(null, await listAvailablePacks(packsDir))` — как это уже делает
`admin-refresh-packs`. При отказе — существующее `admin-pack-error { filename, reason }`, без
нового типа ошибки.

Закрывать редактор при удалении не нужно, и кода для этого не появляется. Редактор
открывается единственной кнопкой, и она всегда открывает **активный** пакет
(`client/src/Admin.tsx`, `setEditingFilename(activePackFilename)`), а активный пакет удалить
нельзя по правилу выше. То есть состояние «удалённый пакет открыт в редакторе» не наступает,
и написать тест, который его по-честному вызывает, не из чего. Появится редактирование
неактивных паков — автозакрытие вернётся сюда вместе с ним.

### Интерфейс

Кнопка «Удалить» в строке пакета в списке `/admin` (`client/src/Admin.tsx`, `admin-packs`),
рядом с выбором пакета. Подтверждение двухшаговое — «Удалить» → «Точно?», — той же
конвенцией, что у анкет игроков (`confirmingDelete`, около строки 1162). В подтверждающем
состоянии подпись говорит про картинки: удаление медиа необратимо и из слова «удалить» никак
не следует.

У активного пакета кнопка выключена, а объяснение («Сначала выберите другой пакет») едет
`title`-ом на обёртке `<span>` вокруг кнопки, **не на самой кнопке**: `disabled`-элемент не
получает mouse-событий, и подсказка на нём не всплывает вообще. Выключенное состояние без
объяснения — это ровно та беззвучная блокировка, которая на живой партии уже стоила проекта
вечера («кот» без второго игрока, `svoya-igra-dev`, «Проверено вживую»), и подсказка, которой
не видно, от неё ничем не отличается. Если и обёртки окажется мало — следующий шаг видимая
строчка-подсказка рядом с кнопкой вместо тултипа, но это уже отдельная правка спеки.

## Тесты

Движок (`server/src/engine.test.ts`):

- `cancel-question` с `requesterId: null` закрывает вопрос так же, как от ведущего: фаза
  `reveal`, вопрос в `answeredQuestionIds`, очки не изменились;
- `requesterId: null` работает и когда `hostId === null`;
- посторонний игрок по-прежнему получает no-op;
- без активного вопроса — no-op при любом отправителе.

`packs.test.ts`:

- удаление сносит и json, и папку медиа;
- пакет без папки медиа удаляется без ошибки;
- удаление несуществующего файла даёт ошибку.

`server.test.ts`:

- `admin-cancel-question` закрывает вопрос без назначенного ведущего;
- удаление обновляет список паков у всех подключённых;
- отказ для `*.example.json`, для активного пакета, тишина на `../` в имени.

Клиент (`Admin.test.tsx`): кнопка пропуска выключена без активного вопроса и активна с ним;
удаление требует двух нажатий; у активного пакета кнопка выключена. `Player.test.tsx`:
надпись кнопки — «Пропустить вопрос».

## Что сознательно не делается

- Удаление пакетов с телефона ведущего — там только выбор; лишний повод снести пак случайным
  тапом посреди игры.
- Механика «снять вопрос и вернуть его на табло» — это другое правило, не запрашивалось.
- Уборка осиротевших папок в `packs/media/` от пакетов, удалённых мимо кнопки (руками, в
  прошлом). Разовая ручная операция, кодом не оправдана.
- Подтверждение у кнопки пропуска вопроса — цена ошибки один вопрос, цена лишнего тапа
  посреди партии выше.
