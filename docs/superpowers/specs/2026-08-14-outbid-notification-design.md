# Уведомление о перебитой ставке — дизайн

Небольшая идея из `docs/ideas.md` («Уведомление о перебитой ставке в аукционе»), одобрена в
брейнсторминге 2026-08-14. Достраивается поверх уже сыгранной и слитой вехи 5
(«Вопрос-аукцион», `docs/superpowers/specs/2026-08-13-auction-design.md`) — сама механика
торгов не меняется, это чисто клиентское UX-дополнение.

## Правило

Пока у игрока активна фаза `'auction-bidding'`, он следит за
`game.auctionHighestBidderParticipantId`. Если это поле **было равно его собственному
`selfId`, а стало кем-то другим** — значит его ставку перебили. В этот момент показывается
персональное уведомление: **только тому, кого перебили**, никому больше — остальные
участники торгов и так видят текущего лидера в `bidHint` («Текущая ставка: N (Имя)»),
дублировать это для всех не нужно.

Уведомление — короткий тост в правом верхнем углу экрана, не блокирующий остальной интерфейс,
с текстом **«Вашу ставку перебили — {имя нового лидера} поставил {сумма}»**. Гаснет сам через
**4 секунды**, без действия пользователя.

Таймер хода в торгах уже даёт каждому полные свежие `AUCTION_BID_TIMER_MS` (20 секунд) на
свой следующий ход, независимо от того, был он перебит или нет (`Room`'s `PHASE_TIMER`
перезаводит таймер на каждый переход хода — `server/src/room.ts`, `afterBidOrPass` в
`server/src/engine.ts`). Уточнено при брейнсторминге: перебитого участника это никак не
поджимает сильнее остальных, специальной логики продления таймера не требуется.

## Инвариант, который эта идея не трогает

Никаких изменений в `server/src/engine.ts`, `server/src/room.ts`, `server/src/protocol.ts`
или `server/src/server.ts`. Всё нужное уже приходит в `GameStateView` (поле
`auctionHighestBidderParticipantId`, добавлено вехой 5) — задача чисто клиентская, реализуется
в `client/src/Player.tsx` без нового серверного события.

## Механизм обнаружения

`Player.tsx` уже хранит `selfId` и получает `game.auctionHighestBidderParticipantId` на
каждый рендер через `useRoomConnection()`. Обнаружение перехода «моя ставка → чужая» требует
знать предыдущее значение поля между рендерами — для этого `useRef`, не `useState` (само
предыдущее значение в разметке не участвует, только в сравнении внутри эффекта):

```ts
const previousHighestBidderRef = useRef<string | null>(null);
const [outbidNotice, setOutbidNotice] = useState<{
  newLeaderName: string;
  amount: number;
} | null>(null);

useEffect(() => {
  const previous = previousHighestBidderRef.current;
  const current = game?.auctionHighestBidderParticipantId ?? null;
  previousHighestBidderRef.current = current;
  if (
    game?.phase === 'auction-bidding' &&
    previous === selfId &&
    current !== null &&
    current !== selfId
  ) {
    setOutbidNotice({
      newLeaderName: nameOf(current),
      amount: game.auctionHighestBid ?? 0,
    });
  }
}, [game?.auctionHighestBidderParticipantId, game?.phase, selfId]);

useEffect(() => {
  if (!outbidNotice) return;
  const timer = setTimeout(() => setOutbidNotice(null), 4000);
  return () => clearTimeout(timer);
}, [outbidNotice]);
```

Тот же двухшаговый паттерн («флаг включается по условию → отдельный таймер гасит его»), что
уже используется для `falsestart` в `client/src/useRoomConnection.ts` — разница только в том,
что здесь обнаружение целиком клиентское (нет отдельного серверного сообщения, вроде
`{ type: 'falsestart' }`), а не приходит с сервера.

**Почему `previous === selfId` как условие, а не «поле вообще изменилось».** Не любое
изменение `auctionHighestBidderParticipantId` — это «меня перебили»: например, если поле
меняется с `null` на кого-то (самая первая ставка в аукционе) или с чужого id на другого
чужого (двое торгуются, я давно спасовал и слежу со стороны) — это не касается меня лично, и
уведомление не нужно. Условие `previous === selfId` — единственный случай, когда именно я
только что был лидером и им быть перестал.

**Почему сброс `previousHighestBidderRef` не обнуляется отдельно между разными аукционами.**
Не требуется: `game.phase` в проверке уже гарантирует срабатывание только внутри одной
непрерывной фазы `'auction-bidding'` — как только фаза меняется (аукцион завершился), условие
`game?.phase === 'auction-bidding'` ложно, и следующий аукцион начнёт сравнение заново с
`auctionHighestBidderParticipantId === null` (сброшенным полем — Task 3/4 вехи 5, `revealQuestion`
сбрасывает все аукционные поля), так что случайное срабатывание из прошлого аукциона
структурно невозможно.

## Клиент — разметка и стили

Рендерится один раз рядом с остальным содержимым `Player()`, не внутри конкретного `case`
`phaseContent`-переключателя — уведомление должно быть видно поверх любого экрана в момент,
когда сработал переход (игрок может быть на экране ожидания хода в тот момент, когда его
перебили, — оно не привязано к конкретной фазе-ветке рендера, только к событию).

```tsx
{
  outbidNotice && (
    <div className="player-toast" role="status">
      Вашу ставку перебили — {outbidNotice.newLeaderName} поставил{' '}
      {outbidNotice.amount}
    </div>
  );
}
```

`role="status"` — как и у уже существующих `player-alert` (`role="alert"`) сообщений в этом
же файле, для единообразия с доступностью, но `status` (не `alert`), поскольку это не ошибка,
не требует немедленного прерывания скринридера.

CSS-класс `.player-toast` (новый, `client/src/index.css`, рядом с `.player-alert`):

```css
.player-toast {
  position: fixed;
  top: 16px;
  right: 16px;
  max-width: min(320px, calc(100vw - 32px));
  padding: 12px 16px;
  border-radius: 8px;
  background: var(--bg);
  border: 1px solid var(--border);
  box-shadow: var(--shadow);
  font-size: 15px;
  z-index: 10;
}
```

Использует уже существующие переменные темы (`--bg`, `--border`, `--shadow`) — тёмная тема
подхватывается автоматически, отдельного `@media (prefers-color-scheme: dark)`-блока не
требуется.

## Тестирование

`client/src/Player.test.tsx` (первый тест в этом файле, которому нужны фейковые таймеры —
паттерн `vi.useFakeTimers()`/`act(() => vi.advanceTimersByTime(...))`/`vi.useRealTimers()` уже
есть в `client/src/useRoomConnection.test.ts`, используется тем же способом):

- перерендер с переходом `auctionHighestBidderParticipantId` с `selfId` на другого участника
  во время `'auction-bidding'` показывает тост с текстом «Вашу ставку перебили — {имя}
  поставил {сумма}»;
- через `advanceTimersByTime(4000)` тост пропадает из DOM;
- переход с `null` на кого-то (самая первая ставка) — тост **не** показывается;
- переход с чужого id на другого чужого id (я не был лидером) — тост **не** показывается;
- переход, когда лидером стал я сам (`current === selfId`) — тост **не** показывается (это не
  проигрыш, а выигрыш хода).

## Отказы

**Игрок перезагрузил страницу в момент, когда тост должен был появиться.** Тост — чисто
локальный React-стейт, переживает только текущую сессию компонента. Пропущенное уведомление
не критично: текущий лидер и сумма всё равно видны в `bidHint` на экране ожидания, тост —
дополнительное усиление внимания, а не единственный источник этой информации.

**Меня перебивают несколько раз подряд, быстрее чем гаснет предыдущий тост.** Второй
`useEffect` пересоздаёт таймер на каждое новое значение `outbidNotice` (зависимость в
массиве deps), так что новое уведомление корректно продлевает показ на свежие 4 секунды с
актуальным текстом, а не показывает устаревшую сумму дольше нужного.
