# Contributing

## Ветки

`feature/<название>`, `fix/<что-чинится>`, `hotfix/<что-чинится>`. Единственная
долгоживущая ветка — `main`.

## Коммиты

[Conventional Commits](https://www.conventionalcommits.org/). Примеры:

- `feat: голосование по верности ответа`
- `fix: не открывать кнопки повторно после фальстарта`
- `chore: обновить зависимости`

**Заголовок PR становится записью в changelog.** При squash-merge заголовок PR — это то, что
попадёт в коммит на `main`, а Release Please читает именно оттуда. `feat: запомнить токен
переподключения игрока` через полгода читается осмысленно; `feat: правки сервера` — нет.
Никто не пишет changelog руками, так что качество заголовка PR — это и есть качество
changelog.

## Каждое изменение — через PR

Включая соло-работу. PR — это точка, где реально запускается CI, а не формальность.

**Хотфикс идёт тем же путём** — ветка от `main`, PR, зелёный CI, мерж. Это не обход защиты:
хотфикс пишется под давлением, на уже сломанной системе — то есть ровно в тех условиях, когда
случайно сломать что-то ещё вероятнее всего. Прогон CI стоит меньше минуты, экономия на нём
меняет известную маленькую задержку на непредсказуемо большую.

Исключение — только если сам CI недоступен или сломан. Тогда есть `enforce_admins`-обход
(см. настройки защиты ветки на GitHub), но это крайний случай, а не привычка.
